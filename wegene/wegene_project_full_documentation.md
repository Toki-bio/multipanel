## 1. Executive Summary

This project started from a large WeGene report PDF and associated structured files. The goal was to evaluate whether WeGene consumer trait content could be converted into a structured, auditable, scientifically cautious catalog suitable for further commercial/non-medical MVP exploration.

The workflow progressed from raw PDF/structured extraction through normalization, trait classification, medical-vs-non-medical routing, MVP candidate extraction, external annotation, safety screening, and strict second-pass filtering.

The most important current result is:

```text
107 original non-medical MVP candidate traits
252 original MVP rsIDs

After Ensembl + ClinVar + GWAS QC:
36 automatic candidate traits

After stricter second-pass GWAS-context review:
20 final automatic candidate traits
16 Tier 2 caution traits demoted to manual review
15 traits removed from automatic MVP pending manual review
```

The current `20 final automatic candidate traits` are **candidate-only**, not customer-ready. Before customer use, the panel still requires:

- PharmGKB / CPIC drug-response screen.
- HGNC / dbSNP cleanup.
- Manual evidence and wording review.
- Final product/legal disclaimer review.
- Separate ancestry/population validation, especially for Uzbek population relevance.

No private genotype data was used for public safety-screen API queries.

### 18.2 What “Automatic Candidate” Means

`automatic_mvp_candidate` means:

- Passed current non-medical safety gates.
- Not obviously medical/sensitive after Ensembl, ClinVar, GWAS, and second-pass GWAS-context review.
- Candidate for demo/internal MVP use.

It does not mean:

- Clinically validated.
- Customer-ready.
- Fully evidence-reviewed.
- Population-validated for Uzbek users.
- Cleared for regulatory/product launch.

## 22. Known Limitations

### 22.1 Source Limitations

- WeGene source content is consumer-report oriented.
- WeGene marker inclusion is not independent scientific validation.
- PDF text extraction is imperfect.
- Structured files are cleaner than PDF extraction but still need external validation.

### 22.2 Annotation Limitations

- Ensembl did not resolve all rsIDs.
- 14 rsIDs still need dbSNP/NCBI follow-up.
- Some current/merged rsIDs required mapping.
- Gene symbols remain incomplete for some markers.
- HGNC cleanup has not yet been completed.

### 22.3 Safety-Screen Limitations

- ClinVar screen depends on parsed public records and parser correctness.
- GWAS Catalog screen depends on trait-name keyword logic.
- Second-pass GWAS context improved safety but is still keyword-based.
- PharmGKB / CPIC screen is still pending.
- gnomAD allele frequency is still pending and should be used only after coordinates/alleles are stable.

### 22.4 Product Limitations

- Evidence strength has not been manually reviewed for all final candidates.
- Effect/risk alleles have not been finalized.
- Report wording has not been finalized.
- Population-specific validity for Uzbek users has not yet been assessed.
- No customer-facing claim should be made from this pipeline alone.
